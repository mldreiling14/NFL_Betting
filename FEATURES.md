# NFL Win Probability Model — Feature Reference

This document describes every variable in the `games_with_features` table, produced by running:

```bash
python src/fetch_data.py
python src/build_features.py
```

Source data comes from [`nflreadpy`](https://github.com/nflverse/nflreadpy), covering the 2015–2025 seasons (3028 games, 118 columns as of this revision). Live predictions for upcoming games are generated by `src/predict.py`, served via the Streamlit app (`app.py`).

---

## Plain-Language Glossary

- **EPA (Expected Points Added)**: how much a play helped or hurt a team's scoring chances vs. expectation.
- **Elo rating**: a "power ranking" number, borrowed from chess. Starts every team at 1500; beating a strong team raises it more than beating a weak one.
- **Rolling average**: how a team/player has done *lately* (e.g. last 5 games), not full-season or career numbers.
- **Correlation**: a number from -1 to +1 measuring how strongly two things move together. The biggest single correlation in this whole project is about 0.19 — NFL outcomes are genuinely hard to predict.
- **Leakage-free**: a feature only ever uses games *before* the one being predicted.
- **Depth chart**: a team's own official ranked list of who plays each position — more reliable than "whoever played most recently."
- **Calibration**: whether a model's stated probability matches reality (e.g. do "70% chance" predictions actually come true ~70% of the time?).
- **CPOE / NextGen Stats**: NFL player-tracking data (from chips players wear) measuring physical movement — separation, time to throw, etc. — rather than box-score outcomes.

### A full round of "how do we improve accuracy further" (this revision)

A systematic investigation was run covering algorithm choice, feature selection, calibration, and several new feature ideas. Documented here in full so none of this needs to be re-attempted blindly:

**Didn't help:**
- **L1-regularized logistic regression**: cross-validation chose almost no penalty (`C≈167`), zero features shrunk to zero. Accuracy identical to plain logistic regression (67.9% vs 67.7%). *The existing feature set isn't carrying obvious dead weight.*
- **Random Forest / XGBoost**, re-tested on the full mature feature set: all algorithms within ~1pt of each other under `TimeSeriesSplit` CV (62.0–62.9%). *Algorithm choice is not the lever — stick with logistic regression.*
- **Isotonic calibration**: didn't fix a real, well-supported gap in the 40–50% predicted-probability range (model says ~45%, actual home win rate ~32%, n=100+). **Documented as an unresolved, known limitation** — may simply reflect that near-coin-flip games are inherently the hardest to call, or may be revisitable with more seasons of data.
- **Red zone TD rate** (built from play-by-play, per-drive): real signal (57.9% vs 53.0% home win rate) but redundant with Elo/point differential, -0.2pts.
- **Two-minute-drill comeback rate**: real signal after fixing a leakage bug (56.9% vs 52.9%), redundant, -0.7pts.
- **Explicit matchup interaction terms** (`home_off_rating - away_def_rating`, computed by hand): -1.4pts. Logistic regression can already approximate this combination from the separate offense/defense inputs; handing it the pre-computed version just adds a redundant, correlated column.
- **Ensembling logistic regression with XGBoost** (simple probability averaging): -3.8pts. XGBoost alone is meaningfully weaker on this feature set (61.8%), so blending drags the stronger model down rather than adding complementary signal.
- **NextGen Stats** (player-tracking data): tested 5 metrics — QB time-to-throw, QB aggressiveness, WR separation, WR YAC-over-expected, RB rush-yards-over-expected. All showed weak correlations (strongest was 0.08, `away_aggressiveness`). Building and testing the strongest candidate (QB aggressiveness) in the full model: no gain (68.2% → 68.1%).

**Did help — refining the existing best feature, not adding new ones:**
- **Margin-of-victory Elo**: standard win/loss Elo treats a 1-point win the same as a 30-point blowout. Switching to the FiveThirtyEight NFL formula (update scales with `ln(margin+1)`, dampened by how large the pre-game rating gap already was) gave a real, if modest, gain (+0.2pts) and a more historically sensible rating (2016 Cleveland's Elo dropped from ~1364 under plain Elo to ~1232–1252 under MOV — a more accurate penalty for a team that likely lost many games badly).
- **Splitting Elo into separate offense/defense ratings**: instead of one combined team-strength number, track two — offense (points scored vs. expectation, adjusted for opponent defense) and defense (points allowed vs. expectation, adjusted for opponent offense). Adding this *alongside* combined Elo hurt (-1.2pts, redundant/conflicting information) — but *replacing* combined Elo with it entirely gave a further real gain (+0.3pts on top of MOV Elo). **This is the current production Elo implementation.**

**The clear, honest takeaway from this whole investigation: the real gains came from refining the model's single best signal (Elo) twice in succession, not from accumulating more unrelated stats, more complex algorithms, or clever combination tricks. For this project's data size (~2500-3000 training games) and feature count, "build a better team-strength rating" is a meaningfully higher-leverage direction than "add another feature" or "try a fancier model."**

## ⚠️ General Rule: "Conditional" Features Require Gap-Aware Projection

Discovered independently twice (star WR injury, two-minute-drill comeback). Some features only naturally have a value in a specific **triggering situation** (a player is injured, a team is trailing late). Merging such a feature directly by `game_id` means the mere *presence* of a value leaks the outcome — e.g., a team only having a "comeback rate" value for games where they were trailing late means non-missing values are disproportionately attached to games the team was already losing.

**Fix:** use `pd.merge_asof(..., direction='backward')` to project each team's/player's last known value forward across **every** game they're part of, not just the games where the trigger happened. Check for this risk before building any future injury- or rare-situation-based feature.

### ⚠️ Team-code convention warning
- **`load_team_stats`, `load_player_stats`, `load_snap_counts`**: backfill to the current code. Merge on `home_team_std`/`away_team_std`.
- **`load_pfr_advstats`, `load_nextgen_stats`**: use the actual code at the time. Merge on raw `home_team`/`away_team`, or verify via `team_abbr` matching against a team-game lookup.

## Engineered Features (Currently in the Model)

### Team-Strength Ratings — `add_elo_features` **(current implementation)**
Split offense/defense ratings, replacing combined Elo. Each team gets two separate numbers, both starting at 0 (league average):
| Column | Description |
|---|---|
| `home_off_rating_pre` / `away_off_rating_pre` | Points scored above/below league average, adjusted for opponent defense quality |
| `home_def_rating_pre` / `away_def_rating_pre` | Points allowed below/above league average, adjusted for opponent offense quality |

Updates use actual-vs-expected points each game, with a margin-of-victory-style learning rate (`k_off_def=0.05`), and revert 1/3 toward 0 at each season boundary. Historically validated: 2016 Cleveland's defense settles around -3.4 to -3.9, near the bottom of the real league range (~-4.8 to +4.9). **Kept as two separate numbers (not recombined) since a future live in-game model would likely want offense/defense tracked independently.**

*(Prior implementations — plain win/loss Elo, then margin-of-victory combined Elo — are retired; see Model Performance Summary for the reasoning trail.)*

### Team Recent Form, QB, RB, WR/TE, Injuries, Defense, Coaching, Rest, O-Line, DB/WR Matchup, Star Injuries
Unchanged this revision — see prior documentation revisions or the codebase (`features.py`) for full detail on each.

### Weather & Climate Shock, Red Zone Efficiency, Two-Minute-Drill Comeback Rate — built, NOT in production model
All three are real, verified signals, all redundant with team-strength ratings once combined in the full model. Code preserved for reference; excluded from `train_model.py`'s `FEATURE_COLS`.

## Live Prediction Pipeline (`src/predict.py`)

### ⚠️ Bug history: "most recently played" vs. "actual current starter"
Fixed for **QB**, **WR**, **CB** using `nfl.load_depth_charts()` instead of "whoever played most recently" (breaks when an injured starter is replaced by backups late in a season — real example: KC's Mahomes injury). **RB** team-aggregate stats confirmed not to need this fix.

### Elo section updated to match production model
`build_snapshots()`'s rating calculation now builds the split offense/defense ratings (matching `add_elo_features`), not the retired combined-Elo version. Requires `import numpy as np` at the top of `predict.py`.

**Current limitation:** star-injury features default to healthy (`0`) in all live predictions, since real injury designations aren't published until close to game day.

## Known Data Quality Notes

- **Relocated franchises**: see team-code convention warning above.
- **Missing values**: filled with column means (`SimpleImputer`), except `home_coach_h2h_wins` (neutral `0.5`).
- **"Primary player" selection ties**: filter to the correct position/group with `inner` merge before selecting.
- **Live snapshot aggregation order matters**: team-level features must aggregate to one row per team-game *before* rolling.
- **Conditional/triggered features need gap-aware projection** — see dedicated section above.
- **NextGen Stats team-code matching**: match by `team_abbr` + season + week against a team-game lookup table, NOT by season+week alone — merging without the team key duplicates a single player's stat line across every game played that week league-wide (caught before merging into the model).
- **Vegas comparison caveat**: implied probabilities from moneylines aren't de-vigged/normalized.
