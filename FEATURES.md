# NFL Win Probability Model — Feature Reference

This document describes every variable in the `games_with_features` table, produced by running:

```bash
python src/fetch_data.py
python src/build_features.py
```

Source data comes from [`nflreadpy`](https://github.com/nflverse/nflreadpy), covering the 2015–2025 seasons (3028 games, 116 columns as of this revision). Live predictions for upcoming games are generated by `src/predict.py`, and served via the Streamlit app (`app.py`).

---

## Plain-Language Glossary

- **EPA (Expected Points Added)**: a single number capturing how much a play (or a player's average play) helped or hurt a team's scoring chances, compared to what's typically expected in that situation. Positive = helped; negative = hurt.
- **Elo rating**: a single "power ranking" number for each team, borrowed from chess. Every team starts at 1500. Beating a strong team raises your rating more than beating a weak one — it naturally reflects opponent quality, not just win/loss record.
- **Rolling average (e.g., "last 5 games")**: how a team/player has done *lately*, not their full-season or career numbers.
- **Snap share**: what % of a team's plays a player was on the field for. 90%+ = essentially always playing; 20% = rotational/backup role.
- **Percentile**: where a player ranks compared to everyone else at their position, league-wide. "Top 5%" means better than 95% of their peers by that stat.
- **Correlation**: a number from -1 to +1 measuring how strongly two things move together. Near 0 = no real relationship. The biggest single correlation in this whole project is about 0.19 — a reminder of how much genuine unpredictability the NFL has.
- **Leakage-free**: a feature describing "how a team/player has been doing" only ever uses games *before* the one being predicted — never that game's own result.
- **Depth chart**: a team's own official, ranked list of who plays each position (1st string, 2nd string, etc.) — a more reliable source for "who's really the starter" than just looking at who happened to play in the most recent game (see the QB/WR/CB bug history below).

## Model Performance Summary

Evaluated with a chronological train/test split, using logistic regression.

| Version | Test window | Test Accuracy | Vegas (same window) |
|---|---|---|---|
| Naive baseline (always guess home team wins) | — | 55.0% | — |
| Original feature set | 2022–2023 | 60.1% | 66.3% |
| + Elo ratings | 2022–2023 | 62.7% | 66.3% |
| + Rest advantage | 2022–2023 | 62.9% | 66.3% |
| Extended training data (2015–2023 train) | 2024–2025 | 67.2% | 68.9% |
| + Sack rate + QB pressure rate | 2024–2025 | 67.7% | 68.9% |
| + DB/WR size & coverage matchup | 2024–2025 | 68.4% | 68.9% |
| + Star RB injury | 2024–2025 | 67.4%* | 68.9% |
| + Star WR injury (after fixing the identification bug) | 2024–2025 | **68.0%*** | 68.9% |

*Small fluctuations between 67-68% across these last two rows partly reflect testing on slightly different feature-set combinations along the way, not a strict monotonic improvement — see the individual feature sections below for the specific, controlled A/B comparisons each was based on. The production model (`train_model.py`) includes both.

**A real, live example of why the live-prediction pipeline needed fixing:** comparing Week 1 2026 model predictions against already-published Vegas lines surfaced two large disagreements (KC/DEN, LV/MIA). Investigating KC traced it to the live pipeline picking up an emergency third-string QB (who finished a late-2025 game after Mahomes was injured) as KC's "current" quarterback. Fixing this — plus the same underlying risk for WR and CB identification — moved KC's Week 1 home win probability from 27.9% to 46.0%. See "Live Prediction Pipeline" below for the full fix.

## Core / Identifier Columns

| Column | Description |
|---|---|
| `game_id` | Unique ID for the game (format: `season_week_awayteam_hometeam`) |
| `season` / `week` / `gameday` | Season year, week number, game date |
| `home_team` / `away_team` | Team abbreviations, **original/historical codes** |
| `home_team_std` / `away_team_std` | Standardized codes for relocated franchises — used for `load_team_stats`-sourced data, **not** PFR-sourced data (see warning below) |
| `home_score` / `away_score` | Final score |
| `home_win` | **Target variable.** Baked into `games` table by `fetch_data.py` |
| `home_coach` / `away_coach` | Head coach names |
| `home_rest` / `away_rest` | Days of rest since each team's previous game |
| `div_game` | `1` if divisional matchup |
| `spread_line`, `away_moneyline`, `home_moneyline`, `total_line` | Vegas market lines — benchmark only |
| `roof`, `surface`, `temp`, `wind` | Raw stadium/weather conditions |

### ⚠️ Team-code convention warning

- **`load_team_stats`, `load_player_stats`, `load_snap_counts`**: backfill to the **current** code for all historical seasons. Merge using `home_team_std`/`away_team_std`.
- **`load_pfr_advstats`**: uses the **actual code at the time**. Merge using the raw `home_team`/`away_team`.

| `home_qb_recent_epa` / `away_qb_recent_epa` | +0.15 / -0.15 |

### RB / WR-TE Group Performance — `add_rb_features`, `add_wrte_features`
Team-wide aggregates, snap-share weighted. Confirmed **not** vulnerable to the "wrong player identified" risk described below, since they sum across everyone who played rather than tracking one individual.

### Injuries — `add_injury_features`
| Column | Description |
|---|---|
| `home_qb_injury_flag` / `away_qb_injury_flag` | Starting QB's designation (~2.6% of games) |
| `home_rb_injury_flag` / `away_rb_injury_flag` | Primary RB designation (~5.6%) |
| `home_wrte_injury_flag` / `away_wrte_injury_flag` | Top-2 WR/TE designation (~12%) |

### Star Player Injuries — `add_star_rb_injury_feature`, `add_star_wr_injury_feature`
**New this revision.** Distinguishes "a genuine star is out" from "any primary player is out" — the general injury flags above fire for *any* primary player regardless of talent level, which doesn't capture your original insight that losing a true difference-maker should matter more than losing a rotational player.

**Star RB** — top 10% league-wide by rolling fantasy points (PPR), recalculated fresh every game.
| Column | Real-world check |
|---|---|
| `home_star_rb_injured` / `away_star_rb_injured` | Home win rate 48.7% vs 54.8% overall (n=76) when out. Kept despite a small net accuracy cost (-0.3pts) in isolated testing — real, sensible signal. |

**Star WR** — top 5% league-wide by rolling targets, WR-only.
| Column | Real-world check |
|---|---|
| `home_star_wr_injured` / `away_star_wr_injured` | Home win rate 38.1% vs 54.8% overall (n=21, Out/Doubtful only) when out. Confirmed to genuinely improve accuracy (+0.3pts) after a bug fix — see below. |

⚠️ **Bug history (star WR):** the first version of this feature identified "the primary WR" and their "star" status using *only* games where that player has a real stat row. But an injured player generates **no row at all** for games they miss — so a genuinely injured star became structurally invisible to his own identification check at exactly the moment he was actually out, and the feature ended up measuring almost the opposite of its intent (home win rate went *up* when the "star" was "out" — the reverse of what should happen). **Fixed** using `pd.merge_asof` to project each player's last known snap share and star status forward across every game their team plays, so an injured star's real established role still "counts" right up until the injury check runs. Also switched the injury definition to **Out/Doubtful only** (excluding Questionable, since those players very often still play close to normal).

### Rest Advantage — `add_rest_advantage`
`rest_advantage = home_rest - away_rest`. Small, real, consistent contribution.

### O-Line / Pass Protection — `add_oline_features`
`home_sack_rate_recent`/`away_sack_rate_recent` (full range) + `home_pressure_pct_recent`/`away_pressure_pct_recent` (2018+, raw team codes). +0.5pts together.

### DB/WR Size & Coverage Matchup — `add_db_wr_matchup_features`
**Second-strongest addition** (+0.7pts). Approximates team's primary WR vs. opponent's primary CB (height, weight, real coverage stats). 2018+ only.

⚠️ **Bug history:** originally used a `left` merge that let non-CB defenders into the "primary CB" pool, producing a 300lb "cornerback" who was actually a defensive end. **Fixed with `inner` merge.**

### Weather & Climate Shock — `add_weather_features`
Built and tested, **excluded from the production model** (small net accuracy cost). `cold_shock_game`: home win rate 61.6% vs 54.8% overall (n=219) — real effect, too rare to move the whole model. Planned as a UI badge instead of a model input.

## Live Prediction Pipeline (`src/predict.py`)

Generates real, current predictions for upcoming (not-yet-played) games, using each team's actual current state rather than historical rolling features.

### ⚠️ Bug history: "most recently played" vs. "actual current starter"

The original QB snapshot identified each team's QB by "whoever played in the team's most recent game." This works fine in normal circumstances, but breaks down exactly when it matters most: if a team's real starter is injured late in a season, backups (even third-stringers) finish out the remaining games, and this method picks up **their** weak stats as if they represented the team going forward. Real example: KC's Patrick Mahomes was sidelined for the final weeks of 2025; the naive method identified emergency QB Chris Oladokun (88 yards, -6.8 EPA average) as "KC's current QB" — a massive, misleading distortion.

**Fix:** identify each team's real starter from `nfl.load_depth_charts()` (official, ranked depth charts, `pos_rank == 1`) instead, then look up *that specific player's* own rolling stats from their real recent starts (wherever they occurred). Applied to:

- **QB** — clean single starter per team. Fixed KC's snapshot from -6.8 EPA to a realistic -0.4 EPA; corrected KC's Week 1 2026 home win probability from 27.9% to 46.0%.
- **WR** — clean single WR1 per team. Same fix applied.
- **CB** — depth charts split cornerbacks into `LCB`/`RCB` (no single "CB1"), so both starters' own recent coverage stats are pulled and whichever has the better (lower) completion % allowed is used as "primary." A genuine judgment call, not the only valid approach.
- **RB** — the *team-aggregate* rolling stats (`current_rb`) do **not** need this fix, since they sum across the whole backfield rather than tracking one identified individual (confirmed by directly testing: one anomalous late-season game only mildly diluted KC's real RB snapshot, unlike QB's near-total distortion). A separate `current_rb_starter` (depth-chart RB1) has been added as groundwork for future live star-injury detection, though it doesn't yet affect any prediction, since real game-week injury reports aren't available this far in advance.

**Current limitation:** `home_star_rb_injured`/`away_star_rb_injured`/`home_star_wr_injured`/`away_star_wr_injured` default to `0` (healthy) in all live predictions right now, since real injury designations aren't published until close to game day. This is honest and correct behavior for games far in advance, but means the live pipeline can't yet use these two features' real value until closer to kickoff.

## Known Data Quality Notes

- **Relocated franchises**: see team-code convention warning above.
- **Missing values**: filled with column means (`SimpleImputer`), except `home_coach_h2h_wins` (neutral `0.5`).
- **"Primary player" selection ties**: filter to the correct position/group with `inner` merge before selecting.
- **Live snapshot aggregation order matters**: team-level features built from individual players must aggregate to one row per team-game *before* rolling.
- **"Most recent starter" can be misleading for individually-tracked positions** (QB, WR, CB) — fixed via depth charts. Does NOT apply to team-aggregate features (RB/WR-TE rolling stats).
- **Star-player identification requires gap-aware projection** (`merge_asof`), not direct per-game lookup — otherwise injured stars become invisible to their own "is this a star" check at exactly the wrong moment.
- **Vegas comparison caveat**: implied probabilities from moneylines aren't de-vigged/normalized.
